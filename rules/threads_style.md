## 参照元から取り入れた考え方
- Threads は**テキストのリズム**が主役。改行や短い箇条で、最後まで読める流れを作る
  （出典: sns_threads_winning_patterns.md 1章）
- 商品リンクだけの投稿は不利。**1投稿目で興味を持たせ、ツリー（2投稿目）でリンクへ誘導**する
  （出典: 同 3章③ ツリー投稿での展開）
- 構成は「フック（冒頭1〜2行）→ 本編 → エンド」。エンドの促しは自然に、クレクレ感は出さない
  （出典: sns_writing.md 3章）
- 毎回同じ言い回しにしない。書き出しの切り口を変える（出典: sns_writing.md 4章）

## このリポジトリ固有の必須ルール（finalize で自動検査）
| ルール | 検査 |
|---|---|
| 1投稿目の本文は **100字前後**（改行・ハッシュタグ・URLを除いて70〜130字。85〜115字が目安） | ✓ |
| **1投稿目・2投稿目の両方に `#PR`** を入れる | ✓ |
| 1投稿目にURLを入れない。**2投稿目に候補データの `affiliate_url`**（無ければ `info_url`）を入れる | ✓ |
| 「満室前に」「残りわずか」等の急かす表現は **`urgency_allowed: true`（獲得期限まで7日以内）のときだけ** | ✓ |
| 本文の**数字はすべて候補データにある値**（`allowed_numbers`）。概数・言い換え（「約」「以上」で丸める等）もしない | ✓ |
| 型Bは強みの根拠（`strength_evidence`）を必ず書く | ✓ |

## 楽天アフィリエイトの規約（docs/rakuten_affiliate_rules.md）
- 金額を書くときは人数・泊数・プラン・利用条件額などの前提条件を一緒に書く（`finalize` で検査）
- 楽天トラベルの施設画像（ダウンロード・API取得とも）は投稿に添付しない
- 未公開のキャンペーン情報・セール日程の予想は書かない（過去実績・毎月固定の企画はよい）
- 対象者限定のクーポン情報は共有しない
- デイユース・ミッドナイトプラン、翌々月末より先の宿泊は報酬対象外なので紹介しない

## 自動検査できないが守ること
- 割引額・期間・設備は**候補データの値のみ**。データに無い設備・サービス・雰囲気を書かない
- 強みは `strengths[].evidence` にあるものだけ。「食事の評価」を「朝食が美味しい」に言い換えない
- 最安料金は変動するので、書く場合は「◯月◯日時点」を添える。基本は書かない
- 「最安」「日本一」「必ず」など、データで裏付けられない最上級・断定表現は使わない
- クーポンは**先着・枚数限定の可能性がある**ため、「必ず使える」とは書かない
- 2投稿目には「クーポンは楽天トラベルの施設ページで獲得」程度の案内を入れてよい

## 型
### 型A：割引訴求
- フック: 割引額 or 割引率を冒頭に（例:「【3,000円OFF】」）
- 本編: ホテル名 / エリア（データの住所・アクセスから） / 利用条件額 / 宿泊対象期間
- エンド: 獲得期限 + 自然な促し（期限7日以内なら急かす表現も可）

### 型B：特徴訴求
- フック: 強み（駅近・大浴場など）を冒頭に
- 本編: 強みの根拠となる事実（徒歩◯分、口コミ件数・評価） + ホテル名
- エンド: クーポンがあることを一言（割引額）

### 2投稿目（共通）
```
▼詳細・クーポン獲得はこちら（楽天トラベル）
<affiliate_url>
#PR
```

    }
